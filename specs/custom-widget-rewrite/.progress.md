## Learnings

- All 10 JS files use the wrong pattern (hidden widgets + onDrawForeground)
- Correct pattern: addCustomWidget with draw/mouse/computeSize (verified via rgthree-comfy)
- Custom widget values ARE serialized automatically — no hidden backend widgets needed
- Mouse coordinate system in widget.mouse() needs verification during POC
- cxSliderBank is the most complex node: 8 hidden backend widgets needed because widget.value cannot be an array (arrays signal links in ComfyUI). Single compound UI widget with {serialize: false} manages them.
- cxSeed is unique: standard framework widgets for seed + control_after_generate must be preserved; only buttons become a custom widget
- cxRangeSlider float file stuck at v1.2.2 (missed patch) — moot since being deleted
- Migration detection strategy: presence of sliderProps/seedProps/etc in node.properties indicates old-format workflow — needs POC validation
- Widget replacement (splice out auto-created, add custom with same name) is cleaner than hidden+UI-only pairing, but requires POC to confirm widget order in widgets_values is maintained
- Two-level class hierarchy (CxBaseWidget -> CxNumericWidget -> concrete) is the right depth. Toggle and Seed skip the numeric layer since they have fundamentally different behavior.
- Python backend files need ZERO changes (except __init__.py version bump + range slider removal). Widget names in Python INPUT_TYPES match exactly with JS custom widget names.
- cxSeed's requestAnimationFrame deferred setup is critical for Node 2.0 compatibility — cannot be removed.
- SliderBank's 8 hidden widgets are the only viable serialization approach. widget.value as object is undocumented/risky. 8 named widgets map cleanly to Python kwargs.
- Error boundaries should live in the base class (draw/mouse wrappers calling _draw/_mouse). Subclasses never need try/catch boilerplate.
- v1.x migration detection: check for `properties.current` (slider/dial/toggle) or `properties.value_1` (bank). These keys don't exist in new-format workflows.
- New unified color palette uses blue (#4a90d9) as primary fill for all numeric widgets, green (#5aaa5a) for toggle active state. Intentional simplification from the old blue-for-int/orange-for-float split.
- captureInput(true/false) is NOT needed with custom widgets — framework routes mouse events via widget.mouse() method instead of node-level onMouseDown/onMouseMove.
- POC must validate: widget splice preserves serialization order, mouse pos[1] compares against this.last_y for bounds, computeSize is respected by arrange().
- _getProp() and _resolveTextColor() belong in CxBaseWidget, not CxNumericWidget. CxToggleWidget needs them too, and duplicating utility methods across sibling classes is a maintenance hazard.
- Drag dispatch must be targeted: store _activeDragArea name on pointerdown, dispatch onMove/onUp only to that area. Dispatching to ALL hit areas during drag forces every subclass to guard with index checks (e.g., CxSliderBankWidget's multiple slider rows).
- Cache _lastHeight from draw()'s height parameter instead of calling computeSize() in the _height getter. computeSize() is wasteful on every mouse event for compound widgets. draw() always fires before mouse(), so cached value is current.
- Widget insertion: use widgets.splice(idx, 0, widget) instead of addCustomWidget() for replace-in-place nodes (cxSlider, cxDial, cxToggle) to preserve widgets_values serialization order. POC must verify splice-inserted widgets still receive draw/mouse calls.
- CxSliderBankWidget._updateMiniSlider should use _applySnap(ratio, shiftKey) instead of manual Math.round(value/step)*step. Keeps snap logic in one place and gets shift-invert for free.
- Task planning: `node --check` fails for ES module files. Use `node --input-type=module --check < file.js` for syntax validation.
- Task planning: No linter/type checker/test runner available. Quality checkpoints limited to JS syntax validation and grep-based structural checks.
- Task planning: 42 tasks total across 5 phases. Phase 1 is 60% (42 tasks with 26 implementation + 16 verify/cleanup). POC decision gate at task 1.11.
- Task planning: cxSeed does NOT extend CxNumericWidget despite having numeric behavior — it preserves framework widgets and only adds a `{serialize: false}` button widget. Its button widget extends CxBaseWidget directly.
- Task planning: Old file deletion happens alongside new file creation (same commit for slider, dial, bank) to keep the repo in a working state at each commit.
